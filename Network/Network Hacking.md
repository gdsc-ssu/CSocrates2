## 0. 왜 우리는 뚫리는가?

* **"기능 개발 다 끝났는데요?"** * 우리는 종종 로직이 완벽하게 동작하면 개발이 끝났다고 생각합니다. 하지만 해커는 우리가 의도하지 않은 '예외 상황'을 찌릅니다.

* **보안은 방해물이 아닙니다.**
* 방화벽이나 인증 절차 때문에 개발이 귀찮아질 때가 많지만, 이는 우리 서버을 지키기 위한 최소한의 장치이다. (솔직히 귀찮긴함;;)

## 1. 해킹 이해하기

웹 해킹에는 다양한 분야가 있지만 그중에서도 흔히 언급되는 것 두 가지가 있습니다. 

- 웹해킹
- 포너블 해킹

### 1.1 웹 해킹

웹 해킹은 말그대로 웹 애플리케이션을 대상으로 보안 취약점을 찾고 이를 활용하는 기술입니다. 쉽게 말하면 집에 초대 받지 않은 손님(해커)이 잠기지 않은 문이나 창문(취약점)을 통해
몰래 들어와 집압을 뒤지거나 망가뜨리는 것과 같습니다. 

![[Pasted image 20260228162001.png]]

보안 공격의 대부분은 웹 해킹이며 보안을 하는 기업들은 웹 해킹을 방어 하기 위해 여러 보안 정책과 솔루션을 사용하고 있습니다. 

공격으로는 SQL Injection, XSS 등이 있습니다. 자세한 내용은 아래에서 설명하도록 하겠습니다.


### 1.2 포너블

포너블은 '완벽하게 제어권을 빼앗다'라는 뜻의 은어 Pwn 과 able이 합쳐진 말로, 주로 시스템 해킹(System Hacking)을 의미합니다. 

타겟은 운영체제(os) , C/C++ 로 작성된 소프트웨어, 메모리 구조 입니다.

여기서 c/c++로 작성된 소프트웨어라고 나와있는데 왜 c나 c++이냐면 포너블은 RAM을 조작하고 박살내는 행위 입니다. 그렇기 때문에 메모리를 개발자가 직접 관리해야하는 C/C++로 만들어진 프로그램이 타켓이 됩니다.

**Buffer Overflow**
포너블의 가장 치명적인 공격하나만 살펴보겠습니다. 

정상적인 상황이라면 개발자가 '여기는 사용자 이름을 저장할 공간이고 딱 10 Byte만 들어가게 해" 라고 메모리에 할당을 합니다. 
여기서 해커가 시스템을 탈취하여 10 byte가 아닌 100 byte를 때려 넣게 되면 넘친 데이터가 옆에 있던 다른 중요한 메모리 영역을 덮어버립니다. 

"우리는 C/C++ 안 쓰고 Java랑 파이썬 쓰니까 포너블 공격은 상관 없는거 아니야?"

이렇게 생각하실 수 있는데 위험이 존재합니다. JAVA 나 Python 스크립트는 안전할지 몰라도, 그 코드를 실행해 주는 JVM이나 Python 인터프리터 자체는 C/C++로 만들어져있습니다.
이렇게 기반이 되는 시스템에 포너블 취약점이 터지면 그 위에서 돌아가는 앱은 코드를 아무리 잘 짜도 속수무책으로 털리게 되는 것이죠
그렇기 떄문에 보안팀에서는 서버 os 패치나 취약점 점검을 하게 됩니다.


## 2. OWASP Top 10 

보안을 얘기 할 때 OWASP Top 10는 중요합니다. 그 이유는 가장 빈번하게 발생하는 10가지 보안 취약점 목록이기 때문입니다. 
국제 웹 보안 표준 기구에서 발표하는 Top 10 취약점이며 웹 보안의 기본 지침서와도 같습니다. 10가지는 모두 보지 않고 개발하면서 자주 마주치게 되는 공격 몇가지만 살펴보도록 하겠습니다.

### 2.1 SQL Injection

SQL은 좀 너무 DB스럽기도 하고 이게 유명한 해킹 방법인가? 싶지만은 정말 피해가 크고 지속적으로 발생하는 공격 유형입니다. 해킹의 목적이 사용자의 정보를 터는 것이라면 사용자의 정보는 어디 있을까요? 
바로 DB에 있겠죠? 아 그럼 DB를 터는건가? 싶을 수 있지만 그것은 아닙니다. DB를 털지않고도 취약점을 가지고 정보를 빼내올 수 있습니다. 

SQL 인젝션 공격에 취약점이 발생하는  곳은 웹 애플리케이션과 데이터베이스가 연동되는 부분입니다. 보통 사용자 로그인 부분, 게시물 검색 부분, 무엇인가를 검색하는 부분이 대상이 됩니다. 
아이디와 비밀번호를 입력하는 로그인 부분에서 아이디, 비번을 입력하면 서버에 
`SELECT * FROM USER WHERE ID = "입력한 아이디" AND PASSWORD = "입력한 PWD";` 
형태로 쿼리가 날라가게 될 것입니다. 아이디와 비번이 올바르다면 로그인이 성공하고 유저 값을 반환하게 되겠죠. 

허나 SQL문에는 WWHERE로 입력되는 조건문을 항상 참으로 만들 수 있는 방법이 있습니다. 바로 조건 값에 'OR''='을 입력하는 것입니다. 이 값을 패스워드 부분에 입력하면 비밀번호의 WHERE절은 항상 참이 되면서 로그인이 성공하게 되는 것입니다. 
이것 뿌만 아니라 sql 문이 항상 참이 되는 SQL문은 삽입 공격에 사용될 수 있습니다. 


### 2.2 XSS

Cross-Site Scripting은 많이 들어보셨을 겁니다.
원리는 해커가 악성 스크립트(주로 javascript)를 웹사이트에 삽입하고, 다른 사용자가 해당 페이지를 방문했을 때 작동하게 만듭니다. 
기본적인 개념이 이렇게 되는 것이고 가장 유명한 두가지의 XSS 방식을 살펴보도록 하겠습니다. 

#### (1) Stored XSS

악성 스크립트가 서버에 저장이 되어서 서버로부터 응답이 올 때 스크립트가 실행되는 유형입니다. 
서버에 저장되는 것들은 보통 게시글, 댓글과 같은 정보입니다. 



#### (2) Reflected XSS

악성 스크립트가 서버와 상호작용 없이 브라우저 자체에서 실행되는 취약점으로, 페이지에 포함되어 있는 브라우저 악성코드가 DOM 환경에서 실행됩니다. 

DOM? (Document Object Model, 문서 객체 모델) 
브라우저가 웹 페이지를 렌더링 하는데 사용하는 모델로 HTML 및 XML 문서에 접근하기 위한 인터페이스

Soted XSS및 Reflected XSS는 서버에서 악성 스크립트의 공격이 이루어지기 때문에 위험 징후를 발견할 수 있습니다.  그렇기 때문에 의심하고 또 취약점 보안을 하는 것이 중요합니다. 

#### XSS 방어 

- 입력값 필터링 
	- 악성 스크립트가 삽입되어도 동작하지 않도록 스크립트에 사용되는 <, >, ‘, “ 등의 특수문자는 &It;, &gt; 등의 HTML Entity로 치환하여 입력합니다. 
- WhiteList 필터링
	- 게시판과 같이 HTML 태그 사용이 필요한 경우에는 사용할 태그를 지정하여 해당 태그만 허용하는 방식인 WhiteList 필터링 방식을 적용합니다. 
- 라이브러리 이용
	- XSS 필터 관련 외부 라이브러리를 활용하여 악성스크립트가 삽입되는 것을 방지할 수 있습니다.
	- Lucy-XSS-Filter: WhiteList 방식으로 공격을 방어하는 Java 기반의 오픈 소스 라이브러리
	- OWASP ESAPI: OWASP에서 제공하는 무료 오픈 소스 라이브러리로 JAVA, PHP 등 다양한 언어


## 3. 보안 키워드

보안 부서가 아니더라도, 백엔드/프론트엔드 개발을 하다 보면 무조건 마주치는 보안 개념들이 있습니다. 보안 관련 키워드가 나올 때마다 대충보고 넘겼는데 이제는 그럴 수 없는 위치가 돼버렸네요^^

### 🛑 CORS (Cross-Origin Resource Sharing)

CORS는 정말 많이 마주칠 것 같은데
* 이 CORS 에러가 자꾸 떠서 이걸 전체 허용으로 열어버리는 순간 바로 취약점에 노출되게 됩니다. 
* **보안의 이유:** CORS는 서버가 아니라 **'브라우저'가 사용자를 지켜주는 방패**입니다. 만약 CORS가 없다면, 사용자가 해커의 악성 사이트에 접속했을 때 해커가 사용자 몰래 우리 서비스 API를 마음대로 호출(데이터 탈취 등)할 수 있게 됩니다.
* **해결책:** 귀찮더라도 백엔드에서 정확히 허용할 프론트엔드 도메인만 White-list로 등록해야 합니다.

## 4. 유명한 공격 시나리오

개발 레벨(L7)을 넘어, 인프라와 네트워크(L3~L4) 구간에서는 어떤 일들이 벌어질까요?

### Port Scanning 

![[Pasted image 20260228172301.png]]
포트 스캐닝은 빈집 털이범들이 집의 초인종을 눌러보는 것과 비슷합니다.

* **공격:** 해커가 자동화 툴(Nmap 등)로 우리 서버의 1번부터 65535번 포트까지 전부 찔러봅니다. "어? 3306(MySQL) 포트가 외부 인터넷에 열려있네?"

열려있는 포트만 알고 있다고 해서 해킹이 성공한 것은 아니지만 그래도 집에 주인이 없다는 것을 초인종으로 알아냈으니 마음 편히 무엇인가를 시도해볼 수 있겠죠

해커들은 직접 공격을 시도 한다기 보다는 자동 공격 툴을 이용해서 해킹을 시도합니다. 초당 수천 번씩 아이디와 비밀번호를 대입해서 맞춰보기 때문에 만약 DB의 아이디가 admin이고 비밀번호가 admin123 이런거면 금방 뚫리겠죠

* **방어:** 불필요한 포트는 전부 닫고, 필요한 포트만 **Security Group(보안 그룹)** 이나 방화벽으로 열어둡니다. 특히 DB 포트는 절대 외부 인터넷(`0.0.0.0/0`)에 열어두면 안 됩니다.

실은 요즘 대부분의 포트는 닫아둡니다. 그럼에도 인터넷과 통신을 해야하기 때문에 80(http)과 443(https)을 열어두는데 이런 이유로 웹 해킹 공격이 많은 것입니다.

###  패킷 도청(Sniffing) 과 HTTPS (중간자 공격, MITM)


![[Pasted image 20260228172922.png]]

* **공격:** 카페 공용 와이파이에서 누군가 내 패킷을 훔쳐봅니다. HTTP로 통신하면 비밀번호가 "1234"라는 게 평문으로 다 보입니다.

* **방어:** 그래서 **HTTPS(TLS/SSL)** 가 필수입니다. 클라이언트와 서버가 통신을 시작하기 전에 "우리 이 암호표로 이야기하자"라고 합의하는 과정(TLS Handshake)을 거칩니다.
